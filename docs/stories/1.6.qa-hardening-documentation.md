## Story

**As** the owner of the tool,
**I want** the v1 finalized with integration tests, corner case handling, and a complete README,
**so that** I can rely on the tool daily without surprises and can return to it in months without needing to re-learn how it works.

## Acceptance Criteria

1. Testes de integração cobrem explicitamente os seguintes corner cases, todos com expectativas bem definidas: (a) URL web que retorna 404, (b) URL web que retorna HTML vazio ou quase-vazio (SPA não-renderizada), (c) PDF sem texto (página totalmente imagem, simulando o caso que não será suportado por falta de OCR), (d) arquivo enviado que não é PDF válido, (e) upload excedendo `MAX_UPLOAD_MB`, (f) timeout na conversão.
2. Para o caso (c) PDF sem texto, o sistema retorna um erro claro orientando o usuário de que OCR não está habilitado na v1, em vez de produzir um arquivo vazio.
3. `README.md` é atualizado com seções: Visão geral, Pré-requisitos, Instalação, Como rodar, Como usar (passo a passo com screenshots opcionais; inclui menção ao Swagger UI automático em `http://127.0.0.1:8000/docs` para inspeção do endpoint `/extract` — S4), Troubleshooting (primeira execução baixando modelos, PDFs sem texto, URLs dinâmicas não suportadas), Estrutura do projeto, Limitações conhecidas da v1, Roadmap de v2 (OCR, extração de imagens com descrição via LLM, deploy online).
4. Linter `ruff check backend tests` passa sem erros; `ruff format --check` passa sem alterações pendentes.
5. Toda a suíte de testes (`pytest`) roda em menos de 60 segundos em máquina de desenvolvimento típica.
6. QA Gate rodado por `@qa` retorna verdict PASS ou CONCERNS (não FAIL).
7. O autor executa manualmente 5 fluxos reais de ponta a ponta (3 tipos de fonte + fallback de path + 1 caso de erro) e confirma que cada um produz o resultado esperado.

### Corner Case Mapping

[Source: arch §10.4 + PRD §6 Story 1.6 AC1]

| Caso | Exception | HTTP | Mensagem exata sugerida |
|------|-----------|------|-------------------------|
| (a) URL 404 | `SourceFetchError` | 502 | "URL returned 404. Verify the URL is publicly accessible." |
| (b) HTML vazio / SPA | `ConversionError` | 422 | "Extracted content is empty. JavaScript-rendered pages (SPA) are not supported in v1." |
| (c) PDF scanned | `ConversionError` | 422 | "PDF appears to be scanned without extractable text. OCR is not enabled in v1." |
| (d) Non-PDF upload | `InvalidInputError` | 400 | "Uploaded file is not a valid PDF." |
| (e) Upload > MAX | `UploadTooLargeError` | 413 | "Upload exceeds MAX_UPLOAD_MB (50 MB)." |
| (f) Timeout | `RequestTimeoutError` | 504 | "Extraction exceeded REQUEST_TIMEOUT_SECONDS (60s)." |

Todos respeitam o envelope `{status, code, message, hint}` com `hint` sempre presente (arch §10.2).

### Detecção de "markdown vazio" (AC2)

[Source: arch §10.4 — caso (c)]

O caso crítico é PDF scanned: Docling recebe o PDF, processa as páginas como imagens (sem OCR) e retorna markdown **vazio ou quase-vazio**. Sem detecção explícita, o file_writer escreveria um `.md` com só o frontmatter e corpo vazio.

**Solução:** em `backend/docling_service.py::extract`, após obter `markdown, metadata` do `_run_docling`, verificar:

```python
content_len = len(markdown.strip())
if content_len < 10:  # threshold arbitrário; tune conforme sample real
    raise ConversionError(
        "PDF appears to be scanned without extractable text. OCR is not enabled in v1."
    )
```

Testar via fixture `tests/fixtures/scanned.pdf` (criar nesta story) — verificar que o request POST retorna 422 + mensagem esperada.

### README Structure

[Source: PRD §6 Story 1.6 AC3 + arch §13]

Ordem recomendada:

```
# Docling Extractor

## Visão geral
Wrapper local sobre Docling para extração de .md com frontmatter mínimo.
Pipeline: URL ou PDF → Docling → .md no ./output/. Stateless, single-user.

## Pré-requisitos
- Python 3.11+
- ~1GB de disco livre (modelos Docling)
- Conexão de rede no primeiro boot (download de modelos)

## Instalação
```bash
uv venv
uv pip install -e ".[dev]"
# ou: python -m venv .venv && pip install -e ".[dev]"
```

## Como rodar
```bash
uv run uvicorn backend.main:app --host 127.0.0.1 --port 8000
```
Abrir http://127.0.0.1:8000.

⚠️ Para expor na LAN, mudar host para `0.0.0.0`. Default 127.0.0.1 por segurança (R8).

## Como usar
3 modos na UI:
1. Colar URL → Extract
2. Drag-and-drop PDF → conversão automática
3. Colar caminho absoluto no fallback → Extract

Swagger UI disponível em `http://127.0.0.1:8000/docs` para inspeção direta do endpoint `/extract` (S4).

## Troubleshooting
- **Primeiro boot lento (~2-5 min):** Docling está baixando modelos (~600MB). Normal (NFR6).
- **PDF não gera conteúdo:** pode ser scanned (sem texto extraível). OCR não está habilitado na v1.
- **URL não gera conteúdo:** página pode ser SPA com render em JS. Docling não executa JS.
- **"Address already in use":** outro uvicorn rodando; matar processo ou usar `--port 8001`.

## Estrutura do projeto
(árvore simplificada — refletindo arch §9)

## Limitações conhecidas v1
- Sem OCR (PDFs escaneados)
- Sem batch (1 fonte por requisição)
- Imagens ignoradas
- Sem autenticação / multi-user
- Desktop only
- Não escreve direto no vault (intencional — usuário move manualmente)

## Roadmap v2
- OCR para PDFs escaneados
- Extração de imagens com descrição via LLM
- Deploy online (HuggingFace Spaces / Fly.io)
```

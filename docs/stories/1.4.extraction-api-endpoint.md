## Story

**As a** frontend client,
**I want** a single HTTP endpoint that accepts either a URL or a multipart file upload and triggers the full extraction + write pipeline,
**so that** the UI can submit any of the 3 input types through one clean JSON contract.

## Acceptance Criteria

1. `backend/main.py` expõe `POST /extract` aceitando `multipart/form-data` com **três campos opcionais mutuamente exclusivos**: `url` (string), `file` (upload) ou `local_path` (string — caminho absoluto para PDF no sistema de arquivos local, atendendo ao fallback FR9).
2. O endpoint valida que exatamente um dos três campos foi fornecido — retorna HTTP 400 com mensagem clara se zero, dois ou três estiverem presentes. Para `local_path`, valida adicionalmente que o caminho existe, é legível e corresponde a um arquivo PDF (extensão `.pdf` ou MIME `application/pdf`); falhas retornam HTTP 400 com mensagem acionável.
3. Uploads excedendo `MAX_UPLOAD_MB` retornam HTTP 413 com mensagem clara. A verificação acontece antes de a conversão iniciar.
4. A rota integra, na ordem: `docling_service.extract` → `frontmatter.build` → `file_writer.save`, e retorna JSON `{"status": "ok", "output_path": "<absolute path>", "filename": "<basename>"}` com HTTP 200 em sucesso.
5. Exceptions tipadas da camada de serviço são mapeadas para respostas HTTP claras: `SourceFetchError` → 502, `ConversionError` → 422, qualquer outra → 500. Todas incluem mensagem textual acionável.
6. Timeout global por requisição respeitando `REQUEST_TIMEOUT_SECONDS` do config; excedê-lo retorna 504 com mensagem clara.
7. Testes de integração em `tests/test_endpoints.py` cobrem, via `TestClient` do FastAPI, os **4 cenários de sucesso** (URL HTML, URL PDF, upload PDF local, `local_path`) e os casos de erro (sem input, múltiplos inputs simultâneos, upload oversized, URL inacessível, `local_path` inexistente, `local_path` apontando para arquivo não-PDF).
8. Para cada caso de sucesso no teste, o arquivo é efetivamente criado no output dir (fixture aponta para diretório temporário) e o conteúdo é validado: frontmatter correto + corpo não-vazio.
9. O endpoint `POST /extract` aplica content negotiation via header `Accept`: se o cliente preferir `text/html` (HTMX default) e não preferir `application/json`, retorna partial Jinja2 (`frontend/templates/partials/result_success.html` em sucesso; `frontend/templates/partials/result_error.html` em erro, com status HTTP apropriado). Caso contrário, retorna o JSON definido em AC4/AC5. O handler global de exceptions respeita a mesma regra (referência normativa: arch doc §7.3 + §10.2). Testes cobrem: (a) `Accept: text/html` retorna HTML em sucesso e em erro; (b) ausência de `Accept` retorna JSON (preserva contrato AC4); (c) `Accept: application/json` retorna JSON.

### `POST /extract` Response Contract

[Source: arch §7.2, PRD §6 Story 1.4 AC4]

**200 JSON:**
```json
{
  "status": "ok",
  "output_path": "C:\\...\\output\\example.md",
  "filename": "example.md"
}
```

**Erros (body comum):**
```json
{ "status": "error", "code": "SOURCE_FETCH_FAILED", "message": "...", "hint": "..." }
```

| HTTP | code | Gatilho |
|------|------|---------|
| 400 | `INVALID_INPUT` | Zero ou múltiplos campos; `local_path` inválido |
| 413 | `UPLOAD_TOO_LARGE` | Upload > `MAX_UPLOAD_MB` |
| 422 | `CONVERSION_FAILED` | `ConversionError` |
| 502 | `SOURCE_FETCH_FAILED` | `SourceFetchError` |
| 504 | `REQUEST_TIMEOUT` | Excede timeout |
| 500 | `INTERNAL_ERROR` | Qualquer não mapeada |

### Content Negotiation (AC9)

[Source: arch §7.3]

```python
def _prefers_html(request: Request) -> bool:
    accept = request.headers.get("accept", "")
    return "text/html" in accept and "application/json" not in accept
```

**Regra de precedência:**

| Accept recebido | Response |
|---|---|
| contém `text/html` **e não** `application/json` | HTML partial |
| contém `application/json` **e não** `text/html` | JSON |
| ambos / `*/*` / ausente | **JSON** (default — preserva contrato literal PRD AC4) |

Handler global aplica a mesma regra. Em HTML, body `{code, message, hint}` vira `{{ code }}`, `{{ message }}`, `{{ hint }}` no partial.

### Lifespan & Singletons

[Source: arch §2.2 R2, §3.4]

- `DocumentConverter()` instanciado **uma vez** no startup. Primeira execução baixa ~600MB de modelos (R2) — aceitar, documentar em Story 1.6 README.
- `httpx.AsyncClient` também lifespan-scoped (fechar em shutdown).

```python
from contextlib import asynccontextmanager

@asynccontextmanager
async def lifespan(app: FastAPI):
    app.state.converter = DocumentConverter()
    app.state.http_client = make_http_client()
    app.state.templates = Jinja2Templates(directory="frontend/templates")
    yield
    await app.state.http_client.aclose()

app = FastAPI(lifespan=lifespan)
```

### CPU-Bound Execution

[Source: arch §2.2 R1]

Docling é síncrono CPU-bound. Sem `asyncio.to_thread`, o `/health` trava durante uma conversão. Todo o pipeline fica em threadpool via:

```python
result = await asyncio.wait_for(
    asyncio.to_thread(run_pipeline_sync, ...),
    timeout=settings.request_timeout_seconds,
)
```

`run_pipeline_sync` orquestra extract/build/save. Observação: `extract` é `async` (Story 1.2 §6.3) por causa de `httpx`; ajustar a arquitetura criando um wrapper que chame `asyncio.run` internamente ou mover `httpx` calls para fora do `to_thread`. Padrão recomendado:

```python
async def run_pipeline(...) -> SaveResult:
    er: ExtractionResult = await extract(..., http_client=..., converter=...)
    # build + save são puros → to_thread
    def _persist() -> SaveResult:
        fm = build(er.metadata, er.source, now=datetime.now(tz=...))
        return save(fm, er.markdown, er.metadata, er.source, settings.output_dir)
    return await asyncio.to_thread(_persist)
```

A chamada ao Docling (dentro de `extract`) **dentro** do `_run_docling` já deve usar `to_thread`. Opcional: mover essa responsabilidade para `extract` encapsular o `to_thread` (arch §2.1 A4 sugere "no endpoint" — mas o contrato resulta mais limpo se `extract` encapsular e o endpoint apenas `await extract`).

### `local_path` Validation

[Source: arch §2.2 R4 + §11 Security]

Validar no endpoint (não delegar ao service):
1. `Path(local_path).is_file()`
2. Extensão `.pdf`
3. Magic bytes `%PDF-` (ler primeiros 5 bytes)

Path traversal é irrelevante (single-user local, NFR7). Validação é só contra typos óbvios.

### File Size Check

[Source: PRD §6 Story 1.4 AC3]

Para `file` (upload): checar `file.size` (fornecido pelo `UploadFile`) **antes** de ler o conteúdo. FastAPI/Starlette carrega o upload em memória ou spool-file — mesmo assim, validar cedo evita trabalho.

Para `local_path`: `Path(local_path).stat().st_size` > limite → `UploadTooLargeError`.

# Story 1.1: Project Scaffolding & Configuration

## Status

Ready

## Story

**As a** solo developer setting up the project,
**I want** a minimal FastAPI application skeleton with config, folder structure, and a health endpoint,
**so that** I have a reliable foundation to iterate on without fighting plumbing.

## Acceptance Criteria

1. Repositório inicializado com a estrutura de pastas definida em Technical Assumptions (`backend/`, `frontend/`, `tests/`, `output/`).
2. `pyproject.toml` declara Python 3.11+ e as dependências diretas **com limites superiores de versão** (S2): `fastapi>=0.110,<0.120`, `uvicorn[standard]>=0.27,<0.31`, `docling>=2.0,<3.0`, `httpx>=0.27,<0.28`, `jinja2>=3.1,<4.0`, `python-multipart>=0.0.9,<0.1`, `pyyaml>=6.0,<7.0`, `python-slugify>=8.0,<9.0`, mais dev-deps `pytest>=8.0,<9.0`, `pytest-asyncio`, `ruff>=0.4,<0.5`. Os ranges permitem patches sem drift de major/minor.
3. `backend/config.py` define constantes/env vars para `OUTPUT_DIR` (default `./output`), `MAX_UPLOAD_MB` (default 50), `REQUEST_TIMEOUT_SECONDS` (default 60).
4. `backend/main.py` expõe app FastAPI com endpoint `GET /health` retornando `{"status": "ok"}` e status 200.
5. `uvicorn backend.main:app` sobe sem erros e o `/health` responde corretamente em browser/curl.
6. `.gitignore` exclui `output/`, `__pycache__/`, `.venv/`, `.env`.
7. `.env.example` documenta as variáveis de configuração disponíveis.
8. `README.md` inicial cobre: pré-requisitos (Python 3.11+), instalação, como rodar o servidor, como checar o `/health`.
9. Repositório inicializado com `git init` + commit inicial incluindo `.gitignore`, `.env.example` e toda a estrutura de pastas base (S1). Mensagem do commit segue conventional commits (ex: `chore: initial project scaffolding`).

### Configuration Contract (backend/config.py)

[Source: arch §3.4 Architectural Patterns — Dependency Injection]

```python
# Shape esperado:
class Settings:
    output_dir: Path        # de env OUTPUT_DIR, default Path("./output")
    max_upload_mb: int      # de env MAX_UPLOAD_MB, default 50
    request_timeout_seconds: int  # de env REQUEST_TIMEOUT_SECONDS, default 60

def get_settings() -> Settings: ...
```

Stories seguintes vão sobrescrever `get_settings` via `app.dependency_overrides` nos testes. Manter a função simples e idempotente.

### Health Endpoint

[Source: PRD §6 Story 1.1 AC4, arch §7.1]

`GET /health` → `{"status": "ok"}` com HTTP 200. Liveness simples. Nenhum check de dependências nesta story (Docling converter só é instanciado em Story 1.4 via lifespan).

### Platform & Binding

[Source: arch §3.2, R8 em §2.2]

- Bind default: `127.0.0.1` (nunca `0.0.0.0` por default — R8).
- Documentar no README como mudar para LAN (Story 1.6 cobrirá expansão).

### Dependências Pinadas (rationale)

[Source: arch §4 Tech Stack + PRD §6 Story 1.1 AC2]

Version ranges `>=X,<Y` evitam drift de major/minor mas liberam patches. Evitar `==` (congela bugs corrigidos) e evitar `>=X` sem teto (quebra silenciosa em major release).

### Git Initial Commit

[Source: PRD §6 Story 1.1 AC9, arch §2.3 S1]

Commit inicial deve conter apenas o esqueleto. Sem código funcional de stories posteriores. Mensagem: conventional commits (`chore: initial project scaffolding`).

### Project Structure Notes

Sem divergências entre PRD §4 e arch §9 para os arquivos-alvo desta story. `models.py` e `errors.py` aparecem em arch §9 (não no PRD §4) — eles serão criados nas Stories 1.2 / 1.3 / 1.4; manter apenas o diretório `backend/` pronto nesta story.

### Testing

[Source: arch §12 Testing Strategy]

- Nenhum teste automatizado é requisitado por Story 1.1 (AC apenas pedem smoke manual via curl/browser).
- Os arquivos de teste (`test_*.py`, `conftest.py`, `fixtures/`) só precisam existir como placeholders vazios — `tests/__init__.py` e `tests/fixtures/` são criados para estrutura, sem fixtures commitadas ainda.
- Stack de teste (`pytest`, `pytest-asyncio`, `TestClient`) vem de AC2 mas só começa a ser usada em Story 1.2+.
